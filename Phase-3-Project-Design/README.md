# Phase 3 – Project Design

## Project Name
**Incident Lifecycle Automation in ServiceNow**

## Overview
This phase focuses on defining the problem-solution fit, proposed solution, and solution architecture for the project.

## Key Areas

- Problem–Solution Fit
- Proposed Solution
- Solution Architecture
- ServiceNow Incident Management Lifecycle
- Stakeholder and System Interaction

## Documents

- **Problem_Solution.docx** – Describes the customer segments, constraints, existing problems, root cause, triggers, and how the proposed ServiceNow solution addresses them.
- **Proposed_Solution.docx** – Describes the problem statement, proposed solution, uniqueness, customer impact, scalability, and solution summary.
- **Solution_Architecture.docx** – Contains the ServiceNow solution architecture diagram and explains the interaction between End Users, Service Desk Agents, Level 2 Support, Change Management, and the ServiceNow platform.

## Solution Scope

The design covers:

- Incident creation and classification
- Service and Service Offering setup
- Knowledge and Agent Assist
- Assignment and reassignment
- Level 2 investigation and resolution
- Emergency change handling
- Child incident management
- Knowledge article creation
- SLA tracking
- Related-record validation

## Phase Outcome

The Project Design Phase defines how the identified incident-management problem will be addressed using a structured ServiceNow solution and provides the architecture for the complete Incident Management lifecycle.
