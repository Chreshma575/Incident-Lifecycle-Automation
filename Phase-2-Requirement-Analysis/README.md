# Phase 2 – Requirement Analysis

## Project Name
**Incident Lifecycle Automation in ServiceNow**

## Overview
This phase focuses on analyzing the project requirements, user journey, data flow, functional requirements, non-functional requirements, and technology architecture.

## Key Areas

- Customer Journey Mapping
- Data Flow Diagram (DFD)
- User Stories
- Functional Requirements
- Non-Functional Requirements
- Technology Stack and Architecture

## Documents

- **Customer_Journey_Map.docx** – Describes the user journey from incident reporting to resolution, Knowledge creation, and SLA validation.
- **Data_Flow_Diagrams_and_User_Stories.docx** – Contains the DFD Level 0 and user stories for the Incident Management lifecycle.
- **Solution_Requirements.docx** – Contains the functional and non-functional requirements.
- **Technology_Stack.docx** – Contains the ServiceNow technical architecture, components, and application characteristics.

## Requirement Coverage

The requirements cover:

- Service and Service Offering setup
- Incident creation and classification
- Knowledge and Agent Assist
- Assignment and Level 2 support
- Emergency change creation
- Child incident management
- Incident resolution
- Knowledge article creation
- SLA and related-record validation

## User Stories

The project contains **12 user stories (USN-1 to USN-12)** covering the complete Incident Management lifecycle.

**Total Story Points:** 51  
**Velocity:** 12.75 points/sprint

## Phase Outcome

The Requirement Analysis Phase defines the functional and non-functional requirements, user journey, data flow, user stories, and ServiceNow architecture required for the project.
